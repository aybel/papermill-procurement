🚀 Guía de Migración: De MVC Tradicional a DDD + Hexagonal en Laravel

1. Introducción y Análisis Inicial

Tu arquitectura actual es un monolito modular basado en MVC con una separación en capas muy limpia. Este es el punto de partida perfecto para evolucionar hacia patrones más avanzados como Domain-Driven Design (DDD) y Arquitectura Hexagonal.

Estado Actual vs. Estado Deseado

  • Controllers, Requests, Resources → Adaptadores Primarios (Infraestructura) ✅ Correcto
  • Models (Eloquent) → Mezcla de Dominio e Infraestructura ⚠️ A mejorar
  • Services, DTOs, Policies → Capa de Aplicación ✅ Correcto
⚠️ Cuello de botella: Los Models de Eloquent mezclan lógica de negocio (Dominio) con detalles de persistencia (Infraestructura), creando acoplamiento con la base de datos y Laravel.

2. Estrategia de Migración Incremental (Strangler Pattern)

No intentes reescribir todo. La estrategia más segura es implementar la nueva arquitectura exclusivamente para módulos nuevos y, con el tiempo, migrar los antiguos cuando sea necesario tocarlos.

Estructura Final de Carpetas (Nuevos Módulos)

app/
├── Http/ (Código LEGADO - Intacto)
│   ├── Controllers/
│   └── ...
├── Models/ (Código LEGADO - Intacto)
├── Services/ (Código LEGADO - Intacto)
│
└── Modules/ (NUEVO Código con DDD + Hexagonal)
    ├── Billing/
    │   ├── Domain/           # Corazón del negocio (100% independiente)
    │   │   ├── Entities/     # Ej: Invoice, Payment
    │   │   ├── ValueObjects/ # Ej: Money, Address, InvoiceId
    │   │   ├── Repositories/ # Interfaces (ej: InvoiceRepositoryInterface)
    │   │   └── Events/       # Eventos de dominio
    │   ├── Application/      # Casos de uso
    │   │   ├── UseCases/     # Ej: MarkInvoiceAsPaidUseCase
    │   │   └── DTOs/         # Data Transfer Objects
    │   └── Infrastructure/   # Implementaciones técnicas (Laravel, DB, APIs)
    │       ├── Persistence/  # Repositorios con Eloquent
    │       ├── Http/         # Controladores (Adaptadores Web/API)
    │       │   └── Controllers/
    │       ├── Listeners/    # Escuchas de eventos (Laravel)
    │       └── Providers/    # Service Providers del módulo
    └── Inventory/ (Otro módulo...)

3. Ejemplo Práctico: Creando un Módulo Nuevo "Suscripciones"

Supongamos que el negocio requiere un nuevo sistema de suscripciones. No existe código previo, así que lo haremos bien desde el inicio.

Paso 1: Definir el Modelo de Dominio (Capa Domain)

El dominio es puro PHP, sin dependencias de Laravel.

app/Modules/Subscription/Domain/Subscription.php
<?php

namespace App\Modules\Subscription\Domain;

use App\Modules\Subscription\Domain\ValueObjects\SubscriptionId;
use App\Modules\Subscription\Domain\ValueObjects\UserId;
use App\Modules\Subscription\Domain\ValueObjects\Plan;
use App\Modules\Subscription\Domain\ValueObjects\Status;
use App\Modules\Subscription\Domain\Events\SubscriptionActivated;

class Subscription
{
    private SubscriptionId $id;
    private UserId $userId;
    private Plan $plan;
    private Status $status;
    private \DateTimeInterface $createdAt;
    private array $events = [];

    public function __construct(UserId $userId, Plan $plan)
    {
        $this->id = new SubscriptionId();
        $this->userId = $userId;
        $this->plan = $plan;
        $this->status = Status::PENDING;
        $this->createdAt = new \DateTimeImmutable();
    }

    public function activate(): void
    {
        if (!$this->canBeActivated()) {
            throw new \DomainException('La suscripción no puede ser activada en su estado actual.');
        }
        $this->status = Status::ACTIVE;
        $this->events[] = new SubscriptionActivated($this->id, $this->userId);
    }

    public function cancel(): void
    {
        if ($this->status->isCancelled()) {
            throw new \DomainException('La suscripción ya está cancelada.');
        }
        $this->status = Status::CANCELLED;
    }

    private function canBeActivated(): bool
    {
        return $this->status->canBeActivated();
    }

    public function getId(): SubscriptionId { return $this->id; }
    public function getUserId(): UserId { return $this->userId; }
    public function getPlan(): Plan { return $this->plan; }
    public function getStatus(): Status { return $this->status; }

    public function releaseEvents(): array
    {
        $events = $this->events;
        $this->events = [];
        return $events;
    }
}
app/Modules/Subscription/Domain/ValueObjects/Status.php
<?php

namespace App\Modules\Subscription\Domain\ValueObjects;

enum Status: string
{
    case PENDING = 'pending';
    case ACTIVE = 'active';
    case CANCELLED = 'cancelled';
    case EXPIRED = 'expired';

    public function canBeActivated(): bool
    {
        return in_array($this, [self::PENDING, self::EXPIRED]);
    }

    public function isActive(): bool
    {
        return $this === self::ACTIVE;
    }

    public function isCancelled(): bool
    {
        return $this === self::CANCELLED;
    }
}

Paso 2: Definir la Interfaz del Repositorio (Capa Domain)

Define qué necesita el dominio, no cómo se implementa.

app/Modules/Subscription/Domain/Repositories/SubscriptionRepositoryInterface.php
<?php

namespace App\Modules\Subscription\Domain\Repositories;

use App\Modules\Subscription\Domain\Subscription;
use App\Modules\Subscription\Domain\ValueObjects\SubscriptionId;
use App\Modules\Subscription\Domain\ValueObjects\UserId;

interface SubscriptionRepositoryInterface
{
    public function save(Subscription $subscription): void;
    public function findById(SubscriptionId $id): ?Subscription;
    public function findByUserId(UserId $userId): array;
    public function delete(SubscriptionId $id): void;
}

Paso 3: Implementar el Repositorio en Infraestructura (con Eloquent)

Aquí usamos Eloquent, pero como un detalle de infraestructura. Inyectamos el modelo de Eloquent (SubscriptionModel), que puede ser uno nuevo o uno existente.

app/Modules/Subscription/Infrastructure/Persistence/EloquentSubscriptionRepository.php
<?php

namespace App\Modules\Subscription\Infrastructure\Persistence;

use App\Modules\Subscription\Domain\Subscription;
use App\Modules\Subscription\Domain\Repositories\SubscriptionRepositoryInterface;
use App\Modules\Subscription\Domain\ValueObjects\Plan as PlanVO;
use App\Modules\Subscription\Domain\ValueObjects\Status as StatusVO;
use App\Modules\Subscription\Domain\ValueObjects\SubscriptionId;
use App\Modules\Subscription\Domain\ValueObjects\UserId;
use App\Models\SubscriptionModel;
use App\Models\User;

class EloquentSubscriptionRepository implements SubscriptionRepositoryInterface
{
    public function __construct(
        private SubscriptionModel $model
    ) {}

    public function save(Subscription $subscription): void
    {
        $this->model->updateOrCreate(
            ['id' => $subscription->getId()->value()],
            [
                'user_id' => $subscription->getUserId()->value(),
                'plan' => $subscription->getPlan()->value,
                'status' => $subscription->getStatus()->value,
                'created_at' => $subscription->getCreatedAt(),
            ]
        );
    }

    public function findById(SubscriptionId $id): ?Subscription
    {
        $record = $this->model->find($id->value());
        if (!$record) {
            return null;
        }
        return $this->toDomain($record);
    }

    public function findByUserId(UserId $userId): array
    {
        $records = $this->model->where('user_id', $userId->value())->get();
        return $records->map(fn($record) => $this->toDomain($record))->toArray();
    }

    public function delete(SubscriptionId $id): void
    {
        $this->model->destroy($id->value());
    }

    private function toDomain(SubscriptionModel $record): Subscription
    {
        $subscription = new Subscription(
            new UserId($record->user_id),
            PlanVO::from($record->plan)
        );

        $reflection = new \ReflectionClass($subscription);
        $idProperty = $reflection->getProperty('id');
        $idProperty->setAccessible(true);
        $idProperty->setValue($subscription, new SubscriptionId($record->id));

        $statusProperty = $reflection->getProperty('status');
        $statusProperty->setAccessible(true);
        $statusProperty->setValue($subscription, StatusVO::from($record->status));

        return $subscription;
    }
}

Paso 4: Crear el Caso de Uso (Capa Application)

Los casos de uso orquestan el flujo, pero no contienen lógica de negocio compleja (esa va en las entidades).

app/Modules/Subscription/Application/UseCases/CreateSubscriptionUseCase.php
<?php

namespace App\Modules\Subscription\Application\UseCases;

use App\Modules\Subscription\Domain\Subscription;
use App\Modules\Subscription\Domain\Repositories\SubscriptionRepositoryInterface;
use App\Modules\Subscription\Domain\ValueObjects\Plan;
use App\Modules\Subscription\Domain\ValueObjects\UserId;
use App\Modules\Subscription\Application\DTOs\CreateSubscriptionDTO;

class CreateSubscriptionUseCase
{
    public function __construct(
        private SubscriptionRepositoryInterface $subscriptionRepository
    ) {}

    public function execute(CreateSubscriptionDTO $dto): Subscription
    {
        $existingSubscriptions = $this->subscriptionRepository->findByUserId(
            new UserId($dto->userId)
        );

        foreach ($existingSubscriptions as $sub) {
            if ($sub->getStatus()->isActive()) {
                throw new \DomainException('El usuario ya tiene una suscripción activa.');
            }
        }

        $subscription = new Subscription(
            new UserId($dto->userId),
            Plan::from($dto->plan)
        );

        $this->subscriptionRepository->save($subscription);

        return $subscription;
    }
}
app/Modules/Subscription/Application/DTOs/CreateSubscriptionDTO.php
<?php

namespace App\Modules\Subscription\Application\DTOs;

class CreateSubscriptionDTO
{
    public function __construct(
        public readonly int $userId,
        public readonly string $plan
    ) {}

    public static function fromRequest(array $validated): self
    {
        return new self(
            userId: $validated['user_id'],
            plan: $validated['plan']
        );
    }
}

Paso 5: Crear el Controlador (Capa Infraestructura/Http)

El controlador recibe la request, la valida, llama al caso de uso y transforma la respuesta.

app/Modules/Subscription/Infrastructure/Http/Controllers/SubscriptionController.php
<?php

namespace App\Modules\Subscription\Infrastructure\Http\Controllers;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use App\Modules\Subscription\Application\UseCases\CreateSubscriptionUseCase;
use App\Modules\Subscription\Application\DTOs\CreateSubscriptionDTO;
use App\Modules\Subscription\Infrastructure\Http\Requests\CreateSubscriptionRequest;
use App\Modules\Subscription\Infrastructure\Http\Resources\SubscriptionResource;

class SubscriptionController extends Controller
{
    public function __construct(
        private CreateSubscriptionUseCase $createSubscriptionUseCase
    ) {}

    public function store(CreateSubscriptionRequest $request)
    {
        $dto = CreateSubscriptionDTO::fromRequest($request->validated());

        try {
            $subscription = $this->createSubscriptionUseCase->execute($dto);
            return new SubscriptionResource($subscription);
        } catch (\DomainException $e) {
            return response()->json(['error' => $e->getMessage()], 422);
        }
    }
}
app/Modules/Subscription/Infrastructure/Http/Requests/CreateSubscriptionRequest.php
<?php

namespace App\Modules\Subscription\Infrastructure\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class CreateSubscriptionRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'user_id' => 'required|exists:users,id',
            'plan' => 'required|in:basic,premium,enterprise',
        ];
    }
}
app/Modules/Subscription/Infrastructure/Http/Resources/SubscriptionResource.php
<?php

namespace App\Modules\Subscription\Infrastructure\Http\Resources;

use Illuminate\Http\Resources\Json\JsonResource;
use App\Modules\Subscription\Domain\Subscription;

class SubscriptionResource extends JsonResource
{
    public function toArray($request)
    {
        /** @var Subscription $subscription */
        $subscription = $this->resource;

        return [
            'id' => $subscription->getId()->value(),
            'user_id' => $subscription->getUserId()->value(),
            'plan' => $subscription->getPlan()->value,
            'status' => $subscription->getStatus()->value,
            'created_at' => $subscription->getCreatedAt()->format('Y-m-d H:i:s'),
        ];
    }
}

Paso 6: Registrar Dependencias (Service Provider)

Usamos el contenedor de Laravel para enlazar las interfaces con sus implementaciones.

app/Modules/Subscription/Infrastructure/Providers/SubscriptionServiceProvider.php
<?php

namespace App\Modules\Subscription\Infrastructure\Providers;

use Illuminate\Support\ServiceProvider;
use App\Modules\Subscription\Domain\Repositories\SubscriptionRepositoryInterface;
use App\Modules\Subscription\Infrastructure\Persistence\EloquentSubscriptionRepository;

class SubscriptionServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->app->bind(
            SubscriptionRepositoryInterface::class,
            EloquentSubscriptionRepository::class
        );

        $this->app->bind(CreateSubscriptionUseCase::class, function ($app) {
            return new CreateSubscriptionUseCase(
                $app->make(SubscriptionRepositoryInterface::class)
            );
        });
    }

    public function boot(): void
    {
        $this->loadRoutesFrom(__DIR__ . '/../Http/routes.php');
        $this->loadMigrationsFrom(__DIR__ . '/../../../database/migrations');
    }
}

Paso 7: Integración con Código Legado

Tu módulo nuevo puede consumir modelos o servicios antiguos sin problemas, manteniendo la dirección de dependencias (el nuevo depende del viejo, pero el viejo no sabe del nuevo).

app/Modules/Subscription/Infrastructure/Services/LegacyUserService.php
<?php

namespace App\Modules\Subscription\Infrastructure\Services;

use App\Models\User;
use App\Modules\Subscription\Domain\ValueObjects\UserId;

class LegacyUserService
{
    public function getUserEmail(UserId $userId): ?string
    {
        $user = User::find($userId->value());
        return $user?->email;
    }

    public function userExists(UserId $userId): bool
    {
        return User::where('id', $userId->value())->exists();
    }
}

4. Beneficios Inmediatos de la Nueva Arquitectura

🧩 Aislamiento del Negocio La lógica crítica vive en Domain y puede ser testeada sin Laravel.
🔄 Flexibilidad Tecnológica Cambiar de Eloquent a otro ORM solo implica crear una nueva implementación en Infrastructure.
🧪 Testabilidad Unitarios: Entidades de dominio y Value Objects se prueban de forma aislada. Integración: Repositorios se prueban con base de datos de testing.

Ejemplo de Test Unitario de Dominio:

// tests/Unit/Modules/Subscription/Domain/SubscriptionTest.php

test('una suscripción pendiente puede ser activada', function () {
    $subscription = new Subscription(
        new UserId(1),
        Plan::BASIC
    );

    expect($subscription->getStatus())->toBe(Status::PENDING);

    $subscription->activate();

    expect($subscription->getStatus())->toBe(Status::ACTIVE);
});

test('una suscripción activa no puede ser activada de nuevo', function () {
    $subscription = new Subscription(new UserId(1), Plan::BASIC);
    $subscription->activate();

    expect(fn() => $subscription->activate())
        ->toThrow(\DomainException::class);
});

5. Cuándo y Cómo Migrar Módulos Antiguos

No hay prisa. Puedes migrar cuando:

  • Necesites añadir una funcionalidad compleja a un módulo antiguo.
  • Corrigiendo bugs en un módulo que se toca con frecuencia.
  • En periodos de baja demanda, eligiendo módulos de bajo riesgo.

Estrategia para migrar un módulo antiguo (ej. ProductsController):

  1. Crear la estructura app/Modules/Product/ con sus subcarpetas.
  2. Mover la lógica de negocio de Product (si la hay) a Domain/Entities/Product.php.
  3. Crear la interfaz ProductRepositoryInterface en Domain/Repositories/.
  4. Mover la lógica de base de datos a Infrastructure/Persistence/EloquentProductRepository.
  5. Mover la lógica de casos de uso a Application/UseCases/.
  6. Crear el nuevo controlador en Infrastructure/Http/Controllers/.
  7. Una vez probado, cambiar la ruta en routes/api.php para que apunte al nuevo controlador.
  8. Eliminar el código antiguo (Controlador, Servicio, etc.) gradualmente.

6. Conclusión y Recomendaciones Finales

✅ Empieza por lo nuevo: Implementa DDD/Hexagonal solo en módulos que desarrolles a partir de hoy.

🚫 No mezcles: Mantén el código legado y el nuevo estrictamente separados.

🎯 Sé pragmático: No fuerces DDD en cada línea; úsalo donde el negocio lo justifique.

📈 Aprende gradualmente: A medida que tu equipo gane confianza, podrán migrar más módulos.

Tu arquitectura actual es una base excelente. Con esta evolución, tendrás un sistema mucho más mantenible, testeable y preparado para el futuro, sin necesidad de una reescritura traumática.
